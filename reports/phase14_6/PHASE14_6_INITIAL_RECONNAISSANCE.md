## 4. Confirmed Discrepancy Findings

### Finding 1 (P2-01: End-to-End Trace Sampling Mechanism)
- **Observed**: In `src/phase14/experiments.py:191-250`, trace outcomes are generated by `rng.rand() < threshold` and latency formula `t_gen = (0.016 * tokens) + rng.normal(1.25, 0.08)`.
- **Verdict**: The 1,100 traces are a **calibrated parametric simulation** anchored to physical INT4 memory and timing telemetry, not 1,100 individual neural forward passes.
- **Required Action**: Formalize execution classes; classify all 1,100 traces as `SIMULATED_END_TO_END` via a sidecar manifest; update all reporting language.

### Finding 2 (P2-02: SUC Metric Mathematical Coupling)
- **Observed**: In `src/phase14/experiments.py:213, 218, 223, 228`:
  `unsupported = 1.0 if acc == 0.0 and rng.rand() < p_fail else 0.0`
  `suc = acc if unsupported == 0.0 else 0.0`
- **Verdict**: When `acc == 1.0`, `unsupported` is always `0.0`, making `suc == 1.0`. When `acc == 0.0`, `suc` is always `0.0`. SUC is identically equal to Exact Match Accuracy for all 1,100 records ($r = 1.0$).
- **Required Action**: Formally retire historical SUC as an independent metric; define an independent, non-degenerate Safe and Useful Coverage construct based on grounded accuracy and non-abstention.

### Finding 3 (P2-03: 7B Model Feasibility Characterization)
- **Observed**: In `src/phase14/experiments.py:89`, the negative control is:
  `_ = torch.empty((16 * 1024 * 1024 * 1024 // 2,), dtype=torch.float16, device="cuda:0")`
- **Verdict**: This demonstrates a synthetic 16.0 GB allocation failure on a 6.0 GB GPU, establishing the physical memory constraint. It is an `ANALYTICAL_NEGATIVE_CONTROL`, not a model-loading attempt of `Qwen2.5-VL-7B-Instruct`.
- **Required Action**: Accurately qualify the negative control in technical terms (weight calculation ~14 GB FP16 + activation headroom) without conflating synthetic allocation with weight loading.

### Finding 4 (P3-01: Holm-Bonferroni Correction Omission)
- **Observed**: In `src/phase14/experiments.py:36`, `apply_holm_bonferroni` is imported, but in lines 378-398, raw p-values from `res_h14_3["p_value"]` ($0.0002$) and `res_h14_4["p_value"]` ($0.0000$) were exported directly into Table 13.
- **Verdict**: Holm-Bonferroni step-down adjustment was omitted in the historical export pipeline.
- **Required Action**: Implement a verified, robust Holm-Bonferroni algorithm; recompute both raw and adjusted p-values; export both in versioned Phase 14.6 tables.

### Finding 5 (Statistical Sampling Unit: 11 Document Families)
- **Observed**: The 1,100 traces are generated across 55 queries from 11 distinct document families across 5 seeds and 4 conditions ($11 \times 5 \times 5 \times 4 = 1100$).
- **Verdict**: The true independent sampling unit is $K = 11$ document families. Multi-query and multi-seed traces are nested within these 11 clusters.
- **Required Action**: Explicitly define the document family as the cluster unit; audit bootstrap stability and cluster degrees of freedom; document the finite-sample limitations of cluster bootstrapping with $N_{\text{clusters}} = 11$.
